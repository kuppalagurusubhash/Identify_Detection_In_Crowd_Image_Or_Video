Project Title

AI-Based Identity Detection and Recognition in Crowd Images and Video Streams

Abstract

This project proposes an AI-based computer vision system capable of detecting and identifying multiple individuals from crowd images, recorded videos, and live camera feeds. The system first detects faces or persons present in each frame and then extracts unique facial features using a deep-learning-based recognition model. These extracted features are compared with previously registered identities stored in a database.

When a match is found, the system displays the person's name, confidence or similarity score, and other permitted information. If no suitable match is found, the individual is marked as Unknown.

The proposed system is designed to work with multiple individuals simultaneously and aims to handle practical challenges such as changes in illumination, facial orientation, partial occlusion, distance from the camera, and variations in image quality. The MVP demonstrates the complete detection-to-identification pipeline and can later be extended for applications such as authorized attendance systems, controlled-access environments, event management, and consent-based identity verification.

Problem Statement

Identifying a particular individual manually from a crowded image or long video recording is difficult and time-consuming.

Traditional systems may work effectively when only one person is standing directly in front of a camera, but their performance becomes more challenging when:

many people appear simultaneously,
faces are small or partially hidden,
people are moving,
lighting conditions change,
faces appear at different angles,
recorded videos contain thousands of frames,
the person being searched for appears only briefly.

Therefore, there is a need for an automated system that can detect multiple people and determine whether any of them correspond to identities stored in an authorized database.

Why InsightFace / ArcFace?

You may initially think of using a simple OpenCV Haar Cascade.

Haar Cascades are useful for learning, but I would not make them the main recognition technology for this project.

A stronger architecture is:

Face Detection
      ↓
SCRFD / RetinaFace

Face Recognition
      ↓
ArcFace / InsightFace

ArcFace generates highly discriminative facial embeddings.

Conceptually:

Person A face
      ↓
ArcFace
      ↓
Vector A

Person B face
      ↓
ArcFace
      ↓
Vector B

Then similarity is measured using something such as cosine similarity.

Matching Logic

Suppose a registered person's embedding is:

Database embedding

and the detected face generates:

Query embedding

Calculate:

$$ CosineSimilarity = \frac{A \cdot B} {\|A\|\|B\|} $$

If similarity exceeds a tuned threshold:

MATCH

Otherwise:

UNKNOWN

Important: do not blindly describe the score as a literal probability such as “95% certain” unless your system has been calibrated that way. In your report, similarity score is a safer technical term.

Important Difference: Detection vs Recognition

This will very likely be asked during your presentation.

Face Detection

Answers:

“Where is the face?”

Example:

[x1, y1, x2, y2]

Face Recognition

Answers:

“Whose face is this?”

Example:

Face → Rahul

Your project requires both.

Detection
     ↓
Recognition
Person Detection vs Face Detection

Your project statement mentions both faces or persons.

These are not identical tasks.

Person detection:

YOLO
↓
detect complete human body

Face recognition:

InsightFace
↓
identify face

A stronger version of the project can combine them:

YOLO
↓
Person Detection

      +

InsightFace
↓
Face Recognition

However, for your MVP, prioritize face-based identity recognition because person detection alone cannot reliably tell you the person's identity.

Handling Crowd Videos

Crowd videos can have the same person appearing in hundreds of frames.

Without tracking:

Frame 1 → Rahul
Frame 2 → Rahul
Frame 3 → Rahul
Frame 4 → Rahul

The model performs unnecessary recognition repeatedly.

A better architecture uses:

Detection
    ↓
Recognition
    ↓
Tracking

For example:

Rahul
Track ID = 17

Then ByteTrack or DeepSORT follows that person across consecutive frames.

That can be added as the next stage after your basic MVP works.

Challenges Mentioned in Your Project

Your screenshots specifically mention issues such as partial occlusion, different orientations and lighting. Your implementation can address them approximately like this:

Problem	Approach
Low light	CLAHE / brightness correction
Different face angles	RetinaFace/SCRFD + ArcFace
Multiple people	Multi-face detection
Small faces	Higher-resolution processing
Partial occlusion	robust embeddings + thresholding
Movement	tracking
Duplicate detections	NMS / tracking
Unknown people	similarity threshold
Large identity database	FAISS

Do not claim that the MVP completely solves occlusion or pose variation. Instead say it is designed and evaluated to be more robust under those conditions.

MVP Development Phases

You can build this in roughly this order:

Phase 1 — Environment and basic detection
Install Python, OpenCV and InsightFace. Detect all faces in one image and draw bounding boxes.
Phase 2 — Face registration
Create a small database of perhaps 5–10 authorized participants, preferably using consented images. Generate and store several embeddings per identity.
Phase 3 — Identity matching
Detect a face, extract its embedding, compare it with the registered database and return the best match or Unknown.
Phase 4 — Crowd image MVP
Detect and recognize several faces simultaneously in a crowd image.
Phase 5 — Video
Read videos frame-by-frame and display recognized identities.
Phase 6 — Web application
Add the Flask API and a simple dashboard for registration, uploads and results.
Phase 7 — Tracking and evaluation
Add ByteTrack/DeepSORT and measure performance under controlled test conditions.

Core Innovation / Strong Point

Instead of describing the project simply as:

“Face recognition using OpenCV”

present it as:

A multi-person identity retrieval pipeline for crowd imagery using deep facial embeddings, similarity search and temporal tracking.

That sounds more accurate to the actual engineering problem and gives you room to demonstrate detection, recognition, database search and video processing.

One important constraint should also be part of the design: use consented/authorized identities, minimize stored personal information, protect embeddings and images, and keep clear retention/deletion controls. The project description itself mentions privacy safeguards, and those protections will also strengthen your report and viva.
